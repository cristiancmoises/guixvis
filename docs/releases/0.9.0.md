# Guixvis 0.9.0

This release concentrates on the work behind browsing: fewer repeated scans,
more reliable graph separation, and clearer resource limits. It keeps the
search and navigation behavior introduced in 0.8.0.

## Relations without repeated rescans

The index now derives the categories of reverse edges once. Dependency
searches, graph projections and package detail responses reuse those categories
instead of repeatedly searching each dependent package's entire input list.
Inputs, propagated inputs and native inputs remain distinct, including edges
that belong to more than one category. Package IDs and result ordering stay
the same.

Local relation filters prepare their query once; an empty filter no longer
needs to lowercase every package name and version. Terminal graph drawing uses
direct neighbor membership, and layout reuses its displacement buffer.

## Graphs that respect dragging

Browser separation leaves pinned nodes in place in both styles. Finishing a
tap, drag, cancellation or pinch restores the pin state that existed before
the gesture. The final bubble adjustment no longer shrinks separated positions
and puts bubbles back on top of one another. If two overlapping nodes are both
pinned, the solver cannot separate them without moving a pin.

## Safer local resource handling

On Unix, cache loading rejects symlinks and non-regular files, including FIFOs,
without waiting for a writer. Existing regular v5 snapshots remain compatible;
the derived relation data does not change the snapshot format or its identity.

The read-only HTTP API rejects non-empty bodies, including chunked payloads,
with a bounded inspection deadline. Search, package and graph work share four
slots. Excess requests return HTTP 503 instead of holding an unbounded queue;
health checks do not need a slot. Local-origin checks, security headers and
bounded gzip responses remain in place.

These changes do not turn the loopback API into an authenticated network
service. It is still intended for local use, and package commands are still
previews to review and copy, not actions the server executes.

## Measurements and checks

Alternating the previous and current release builds on the same 40,926-object
snapshot reduced the sampled `zlib` reverse projection median from 0.63 to
0.46 ms. Decode stayed near 115–116 ms. The comparable JavaScript workload
(128 nodes, 20 ticks) went from 34.50 to 27.03 ms, retaining identical tick
positions and velocities. These are local measurements, not guarantees.
Final separation is deliberately more expensive on dense graphs: keeping
pins fixed and eliminating movable overlaps does more work than shrinking
positions back into a crowded frame.

Regression tests cover multiple input categories, reverse diamonds and cycles,
Unicode filters, deterministic layouts, both graph styles, persistent and
temporary pins, FIFO/symlink cache rejection, real chunked requests, body
deadlines, and request saturation. Real terminal and isolated Chromium checks
exercise navigation, dragging, resizing, mobile widths and pixel densities.

Source downloads, when published, use genuine `.zupt` archives and
`SHA256SUMS`. Local native Guix installation and owner approval precede
publication.
