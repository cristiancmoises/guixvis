# Guixvis 0.7.0

September 24, 2026

This release makes navigation steadier in the terminal and easier to read in
the browser. The package highlighted in Overview remains the anchor while you
explore its dependency and reverse-dependency trees. Moving or paging through
a tree changes that tree's cursor, not the selected Overview package. The
search text stays visible in the header, and graph labels remain useful in a
narrow terminal.

In the terminal graph, `Enter` follows a node and `+`/`−` set depth when the
search box is empty. The followed root and depth remain when you switch tabs.
Press `g` in Graph to refocus on the Overview package while keeping the current
depth. Selecting a different Overview result starts a graph for that package.

The browser now offers a visible **Back** button and right-click Back on the
canvas. Both return one step through this page's Guixvis graph navigation.
At the first in-app view, Back is disabled, so it cannot leave the site for
an earlier page. Browser Back and Forward remain available. The direction
control still switches between dependencies and dependents. Back restores the
previous package, depth, and direction; it does not toggle between dependencies
and dependents.

The graph style selector offers labeled **Bubbles** and **Rectangles** and
remembers the choice in browser storage. Bubble labels favor the root,
selection, and hubs that fit without collisions. Rectangles carry their names
inside, shortening long ones. Primary-button dragging moves a node, background
dragging pans, and wheel or touch pinch zooms. These gestures do not follow a
package; click or tap a node to do that. The canvas also supports arrow keys
and `Enter`, and the visible Back button works without a secondary mouse button.

No application dependencies were added. Package commands remain previews to
review and copy; Guixvis never runs them while browsing. The web service
remains local to loopback.

## Source archive

The source archive for this release is named `guixvis-0.7.0.zupt`: a level-9,
unencrypted ZUPT export of the tagged commit, accompanied by `SHA256SUMS`.
Check the hash and run `zupt test guixvis-0.7.0.zupt` before extracting.
No `.tar.gz` archive is uploaded as a release asset; forge-generated source
links are separate.

## Verification

The release checks are reproducible with:

```sh
cargo fmt --check
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo test --locked
cargo test --locked --all-features
node --test tests/web_graph_tests.cjs tests/web_app_tests.cjs
emacs -Q --batch -L elisp -l elisp/guixvis-tests.el -f ert-run-tests-batch-and-exit
cargo build --locked --release --all-features
cargo audit
```

The live Guix tests are opt-in (`cargo test --locked --test live_guix_tests
-- --ignored`) because they use the host's Guix installation. On a
32,500-package index, the release-mode search latency check measured 3.3 ms
for its sample; this is a local measurement, not a latency guarantee. See the
[usage guide](../usage.md) for the controls and [publishing guide](../releasing.md)
for archive and native installation checks.

In the September 24 release-candidate checks, the all-feature Rust suite had
70 passing tests and two ignored live checks; both live Guix checks passed
when run separately. Emacs had 19 passing ERT checks, and byte compilation
passed with warnings treated as errors. `cargo audit` checked 235 locked
packages with no reported vulnerabilities or warnings. Chromium checks of
Back, graph styles, native Forward, keyboard navigation, theme contrast,
reduced motion, and layouts from 320 to 1440 pixels found no console errors.
Final build, installation, archive, and forge checks belong to the release
delivery record.
