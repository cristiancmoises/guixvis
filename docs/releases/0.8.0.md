# Guixvis 0.8.0

This version fixes a frustrating browsing problem: moving through one tab
could leave another showing a different package. Overview now holds the
package reference, while each related view keeps its own cursor and filter.

## Search without losing your place

All terminal tabs use explicit Search and Navigate modes. Press `/` to edit
the current query, then Enter or Esc to finish. Letters and digits are always
text while searching, so a package name cannot accidentally trigger a command.
Tab and Shift+Tab work in both modes.

Dependencies and Reverse deps search their complete reachable sets by name
and version. The tree can remain collapsed; the filter still finds deeper
matches. Graph search is deliberately narrower: it filters the current
projection without changing its root or rerunning the layout.

## The actual package objects

The indexer follows Guix package objects rather than resolving edges by name.
Different versions, same-name variants, and private packages reached through
inputs stay separate. Ordinary, propagated, and native inputs are all retained,
including cases where one relationship belongs to several categories.

These are declared inputs for the indexed system, not a store closure or a
derivation/build plan. Extraction problems are reported as diagnostics. The
interface does not call an incomplete index complete.

Browser and Emacs links now carry a package ID and snapshot token. An expired
reference asks for a fresh search instead of silently opening another variant.
Name-only links remain supported. Command previews include versions and warn
when a private or ambiguous object cannot be selected exactly by a Guix shell
specification. They still only copy text; they never execute package commands.

## A quieter terminal graph

The first view starts at depth 1 with fine dotted edges focused on the selection. Wide
terminals pair the canvas with a package list; narrow terminals use the list.
Complete selected names and versions wrap in the detail area, with `[` and `]`
to scroll. Following a package and returning through graph history preserves
the view's depth and filter.

Limits are explicit: 200 nodes including the root, 3,000 edges, and a traversal
work budget. Unknown totals are labeled as unknown. Use the dependency tabs
when you need a complete relation search.

The web keeps its bubble/rectangle selector, normal-zoom lettering, and
right-click Back navigation. Exact identities now survive those interactions.

## Cache and process handling

The v5 snapshot records the selected Guix launcher, system, and all channel
commits. Launcher symlinks are preserved so channel extensions are not lost.
Unverifiable origins and mutable `GUIX_PACKAGE_PATH` modules are marked clearly.
The first start rebuilds the index and leaves the older v4 cache in place.

Subprocess reads now have bounded output, cancellation, deadlines, and owned
process-group cleanup. Terminal control characters in package metadata are
sanitized. Graph work and relation traversal run outside terminal drawing.

## Validation

Regression coverage includes duplicate versions, private variants, cycles,
diamonds, multiple edge categories, chains beyond 2,500 packages, more than
2,000 direct inputs, stale snapshots, and both graph-budget unknown-total paths.
The Rust suites, JavaScript graph/app tests, and Emacs ERT tests cover these
behaviors alongside the existing local-only HTTP protections.

On the local eight-channel Guix environment, extraction produced 41,746 objects
(33,223 catalog entries) with zero diagnostics. An independent Guile comparison
checked 123 object/category combinations, including private variants, without
a mismatch. Real PTY and isolated Chromium checks exercised navigation,
filters, right-click history, and 100% browser zoom at several widths and pixel
densities. Measurements in the README describe this machine, not performance
guarantees.

Source release downloads, when published, use `.zupt` with `SHA256SUMS`.
