# Guixvis 0.6.0

September 23, 2026

This release makes package exploration more useful in the browser and Emacs,
and removes several sources of unnecessary work and confusing behavior.

## Package browsing

The browser has a Packages view with a persistent list of up to 100 search
results. Rows include the synopsis, version, license, and dependency counts.
The detail pane previews commands for `guix install`, `guix remove`,
`guix show`, and `guix shell`, with a copy button for each. Guixvis remains
read-only: the user runs those commands in the intended shell and profile.

Search and package requests now have independent cancellation and response
ordering. Typing while a graph is loading no longer cancels the package load,
and an older result cannot replace a newer search. Malformed links and missing
packages show a usable state instead of breaking the page.

## Performance and correctness

Browser graph layout caches node and radius lookups, removing repeated linear
scans from the force calculation. A settled graph stops requesting animation
frames. Hidden pages and the Packages view also pause graph rendering.

The terminal polls every 16 ms while search is pending, then returns to its
250 ms idle interval. Search replies are consumed without cloning the results.
The search engine selects the best candidates before sorting, handles small
catalogues without spawning worker threads, and preserves a stable ordering
across duplicate package names. Empty indexes, uppercase queries, normalized
Unicode, and pattern prefixes have regression coverage.

Local measurements used the existing 32,500-package snapshot. A release-mode
worker search for `emac` completed in 3.4 ms; snapshot decoding took about
30 ms. Search microbenchmarks varied between runs, so this release does not
claim a fixed percentage improvement in Rust search throughput.

The reproducible browser-layout workload uses 128 nodes, 127 edges, and 20
ticks, with one warmup and the median of seven alternating samples. On this
Linux x86_64 machine with Node 24.18.0, revision `1bce3adc` took **223.92 ms**
and the new code took **34.39 ms**. This measures graph layout code, excluding
browser painting, network requests, and startup. Run it yourself:

```sh
node examples/bench-web.cjs --compare-ref 1bce3adc
cargo run --locked --release --example bench
```

## Themes and Emacs

The browser's new **system** setting follows the operating system's theme.
Explicit choices remain saved. Theme text colors, native control colors,
reduced motion, and mobile keyboard focus have been adjusted together.

Terminal theme changes persist in the user's configuration directory.
`--theme nord` overrides the saved choice for a single run; `NO_COLOR` still
takes precedence.

Emacs now provides `guixvis-search`, `guixvis-package`, and
`guixvis-copy-command`. Results appear in a sortable native table, with package
details and buttons for dependencies, dependents, and packages from the same
module. HTTP requests are asynchronous and have cancellation and timeouts.
The terminal launcher reuses its live buffer. See the [user guide](../usage.md)
for setup and keys.

## Security and maintenance

- Cache writes reserve exclusive temporary files with private permissions.
  Reads retain their size cap even if a file grows during the read.
- The `guix describe` deadline covers output reading, with a separate output
  size limit. A blocked stdout pipe no longer delays the start of the timeout.
- Host and Origin parsing rejects malformed, duplicate, and mismatched
  authorities. Security headers also cover denied requests.
- Gzip negotiation honors quality values, including `gzip;q=0`. Oversized
  compressed responses return an error instead of an empty success response.
- Emacs requests stay on configured loopback addresses, omit cookies, bypass
  proxies, and reject redirects. Homepage launchers accept HTTP(S) URLs.

The minimum declared Rust version is now 1.88, matching the locked dependency
requirements. No new Rust or web dependencies were added. The live latency
test now reads the current binary cache rather than the retired gzip format.

## Verification

The release was checked with formatting and Clippy, 62 tests in the web-enabled
Rust suite, the default-feature suite, both live Guix tests, a release build,
19 Emacs ERT tests, and five
JavaScript graph tests. Emacs Lisp compiles with warnings treated as errors.
The dependency audit reported no known vulnerabilities in the 235 locked
packages using the advisory database available on September 23, 2026.

Chromium checks covered search, copied commands, persistent/system themes,
stale responses, empty and missing-package states, and layouts at 320, 768,
1024, and 1440 pixels. Normal browsing produced no console errors. Native Emacs
search and details were also exercised against the running service and real
package index.

The terminal was exercised in a real terminal session: search, palette
override, saved palette reload, `NO_COLOR`, and clean exit all worked.

The local API has no authentication and should not be exposed publicly. The
Emacs response-size check limits JSON parsing after the response arrives; it
is not a streaming download limit. A subprocess descendant retaining stdout
may outlive the describe caller's timeout. See [SECURITY.md](../../SECURITY.md)
for the intended trust boundaries.
