# Guixvis 0.10.0

This release makes Emacs a practical place to browse Guix packages, not just
a way to launch the terminal or website. The terminal and browser keep their
existing behavior; the new work is in the native editor views.

## Search that stays with your current view

Outstanding requests are cancelled when a native buffer closes or changes
major mode. Each request has a unique identity, so an older response cannot
overwrite a newer search after buffer-local state has been reset. Failures
clear old actionable rows instead of leaving results that look current.

Search shows an object ID and catalog/private marker for each variant.
Same-name packages remain distinct, including object ID zero. Numeric relation
columns keep their numeric sorting, and refresh preserves the selected exact
variant when it is still present. Incomplete extraction, diagnostics and
capped results have visible guidance. A busy server is no longer reported
only as an index that is still building.

## A graph inside Emacs

Press `v` from search or package details. The native graph groups packages by
depth and shows their actual adjacency, with readable names, versions, input
categories and exact IDs. It does not draw a shared dependency as a unique
tree node or hide a cycle behind an invented hierarchy.

`RET` follows a package, `l` returns, `d` switches between dependencies and
dependents, `+`/`-` change depth, and `/` filters the current projection. `p`
opens exact details; `s` searches the whole catalog. Back restores the root,
direction, depth, local filter and selected variant, with a 32-view history.
These views use Emacs' built-in text, button, HTTP and JSON libraries and
inherit its theme. No graph renderer or new package dependency is needed.

The same API limits apply: depth 1–8, at most 200 projected nodes and 3,000
edges. Known, unknown and truncated totals remain visible. A filter is not a
complete dependency search. Package details still list declared direct inputs,
including ordinary, propagated and native categories.

## Validation and limits

Regression tests cover asynchronous view replacement, mode changes, cleanup,
variant identity, metadata failures, graph navigation and stale snapshots.
Both interpreted and byte-compiled libraries are checked; compilation treats
warnings as errors. The Emacs 31 terminal test mocks also accept the optional
argument used by compiled `get-buffer-create` calls.

The release checklist includes live local Guix/Emacs integration, native
Guix installation, Rust and JavaScript suites, actual terminal/browser checks
and fresh screenshots. See [Releasing](../releasing.md) for the commands and
approval boundary. These checks cover tested environments, not a promise that
every Emacs version or third-party local service can never produce an error.

Requests remain loopback-only, cookie-free and non-executing. Graph responses
are validated before buttons are created, and stale references clear history.
The HTTP response-size check occurs after retrieval, not during streaming;
see [Security](../../SECURITY.md) for the remaining boundaries.

Source packages use genuine unencrypted level-9 `.zupt` archives with
`SHA256SUMS`. Local installation comes first; commits, tags, channel updates
and publication wait for the owner's separate approval.
